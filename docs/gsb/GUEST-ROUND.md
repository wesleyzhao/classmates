# Guest practice round

This is an optional experiment and remains off unless both `GSB_GUEST_PREVIEW=true` and `GSB_GUEST_PERSON_IDS` contain 8 to 32 distinct person IDs. The routes and UI are implemented. No real sample or enabling configuration is committed, and the normal class deck remains private. Use a sample explicitly approved for guest visibility. Turning the flag off disables run, finish, claim, and guest media reads. A live exclusion or an ID removed from the allowlist also blocks an existing run.

Each browser receives one eight-face round through a random HttpOnly, SameSite=Lax capability cookie, capped at seven days. Only its hash is stored in `gsb_guest_runs`. A reload returns the same round, including its completed state, and cannot mint another while the cookie and run remain valid. Guest media access requires that cookie, the exact asset ID assigned to a visible target portrait, the current allowlist, and a live non-excluded person row. An older or alternate asset for the same person is not authorized. Do not expose the normal `/api/media` route to guests.

`startGuestRun(db, req, res, deck, {mediaUrl})` accepts the already-filtered latest deck and returns a public run. The optional `mediaUrl(card)` maps an approved card to the guest media route; by default `/api/media/<asset>` becomes `/api/guest/media/<asset>`. `getGuestRun(db, req)` returns the same public shape, or `null` without a cookie. The ready shape is `{id,status:'ready',unranked:true,direction:'face',questionMs:8000,count:8,expiresAt,questions}`. Each question has `id`, `prompt`, `image`, four `{id,label}` choices, and `correctChoice`. The ID is opaque and is not a capability. The cookie is the sole guest credential.

The client sends `{answers:[{questionId,choice,elapsedMs}]}` to `finishGuestRun(db, req, body)`, in question order. Choices are `'0'` through `'3'` or `null`; elapsed time is an integer from 0 through 8000 milliseconds. A null choice must use 8000 milliseconds. A choice at 8000 milliseconds is recorded as a timeout and cannot score. The server validates all eight entries, then calculates 1000 points per correct answer plus up to 500 speed points in 250 ms buckets. The first result is stored atomically; retries return that same result. Completed runs return `status:'complete'`, a `result` containing `score`, `correct`, `count`, `elapsedMs`, `answers`, and `unranked:true`, plus a `claimed` flag.

Client elapsed times are untrusted. These results are personal practice only. They never create a `gsb_match`, rating, leaderboard entry, or Elo change. The parent router must apply its normal POST origin and JSON checks, a reasonable rate limit, `Cache-Control: private, no-store`, and a small body limit. `claimGuestRun(db, req, account)` accepts only normal verified-email session scope and verifies `gsb_accounts.email_verified_at` in the claim update. It attaches a finished result once; a repeated claim by the same account returns the same result, while another account cannot take it. `guestBest(db, account)` returns the highest claimed result whose people remain currently allowed and non-excluded, even after its guest cookie expires. Cleanup may delete expired **unclaimed** guest runs; it must retain claimed rows to preserve saved personal scores. `guestMediaPath(db, req, assetId)` returns an authorized private blob path or `null`; it never returns image bytes.

## Browser and HTTP flow

`GET /api/session` advertises only `{guest:{enabled,count}}`, never sample IDs. The login page shows the invitation only when enabled. The browser dynamically imports `public/gsb/guest-round.js` only after that invitation or `/guest` is opened; disabled normal play incurs no guest-code download or guest API calls.

`POST /api/guest/start` starts or resumes, `GET /api/guest` reads the cookie-bound run, `POST /api/guest/finish` submits the eight-answer log, and `/api/guest/media/ASSET` serves assigned media. Authenticated `POST /api/guest/claim` attaches a completed result; `GET /api/guest/best` reads the account's personal best. All routes return 404 while disabled. Starts are capped at five per IP per hour and 200 globally per day; finishes at twenty per IP per hour. A cookie is a convenience limit, not a defense against someone deliberately clearing it. The fixed sample is what prevents guest retries from exposing the whole cohort.

The client downloads the eight portraits before starting the clock so network waits do not consume a question's eight seconds. Failed startup loading has a retry. Correctness appears immediately, and the next face follows after 280 ms. A timeout advances automatically. The browser stores only the opaque run ID, chosen option indices, elapsed times, and current timer in sessionStorage to resume a refresh; it does not store names, photos, or a login/guest credential there. A failed final submission keeps that log for retry. After a successful finish, the log is removed.

The end screen requires email sign-in to continue or save. The guest cookie carries the completed run through a magic link opened in the same browser. The verified account automatically claims it, gets a saved confirmation on Home, and can see its personal speed-round best under Scores. A different browser cannot inherit that cookie; open the email link in the browser used for the round to save it there.

## Testing without enabling the real experiment

`npx playwright test -c playwright.gsb-guest.config.js` starts an enabled synthetic-only server on port 3139, using `gsb_test_guest`, fictional silhouettes, and a local email outbox. The harness refuses Vercel and other schemas. Ordinary regression tests on 3138 verify the feature-off UI, API denial, and absence of a guest module request. Real guest API integration tests use `gsb_test_guest_api`, fake media bytes, and the normal HTTP handler. No real class photos are made public by these tests.
